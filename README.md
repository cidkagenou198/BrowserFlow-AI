# BrowserFlow AI

A powerful, autonomous browser automation agent with an embedded web UI that translates natural language instructions into Playwright actions.

[![CI](https://github.com/cidkagenou198/BrowserFlow-AI/actions/workflows/ci.yml/badge.svg)](https://github.com/cidkagenou198/BrowserFlow-AI/actions/workflows/ci.yml)
[![Node](https://img.shields.io/badge/node-%3E%3D18.0.0-brightgreen.svg)](https://nodejs.org)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

BrowserFlow AI supports two modes of execution: an offline, zero-dependency parser that translates common browsing instructions into automated tasks, and optional LLM-assisted parsing via Gemini, OpenRouter, or Grok for unstructured instructions.

---

## Features

- **Natural Language Parsing**: Works offline by default using an instruction parser; optional LLM integration (Google Gemini, OpenRouter, Grok/xAI) for complex inputs.
- **Web UI & SSE Streaming**: Built-in control panel with Server-Sent Events (SSE) for streaming logs and step-by-step screenshot previews.
- **Multi-Strategy Element Resolution**: Automatically falls back through semantic locators, text/label matching, placeholder matching, ARIA attributes, and iframe searches.
- **Session Persistence**: Maintains browser profile state across runs or falls back to temporary isolated contexts if profile locks are detected.
- **Docker & CI Ready**: Includes GitHub Actions workflow, Dockerfile, docker-compose, and devcontainer for GitHub Codespaces.

## Supported Actions

| Action | Description | Example |
|---|---|---|
| `navigate_to_url` | Opens a web page or domain | `Open https://github.com` |
| `fill` | Fills input fields by label, placeholder, or name | `Fill username with testuser` |
| `click` | Clicks elements, buttons, or links | `Click on Sign in` |
| `double_click` | Double-clicks an element | `Double click on Submit` |
| `select` | Selects a dropdown option | `Select 'California' from State` |
| `check` / `uncheck` | Toggles checkboxes or radio inputs | `Check 'I agree to the terms'` |
| `search` | Interacts with search inputs | `Search for playwright automation` |
| `scroll` | Scrolls the viewport | `Scroll down` |
| `wait` | Explicit delay | `Wait 3 seconds` |
| `verify_text` | Asserts text exists on page | `Verify text 'Submission complete'` |
| `send_keys` | Sends keystrokes to active element | `Send keys Enter` |
| `click_on_screen` | Clicks viewport coordinates `(x, y)` | `Click at 400, 250` |

## Quick Start

### 1. Installation

```bash
git clone https://github.com/cidkagenou198/BrowserFlow-AI.git
cd BrowserFlow-AI

npm install
npm run install:browsers
```

### 2. Run the Web Interface

```bash
npm start
```

The web console will be available at `http://localhost:3000`.

### 3. Run from the Command Line

```bash
# Headed mode (opens a visible browser window)
node agent.js "Open https://github.com and search for playwright"

# Headless mode
node agent.js "Open https://example.com and verify text 'Example Domain'" --headless
```

## Configuration

By default, BrowserFlow AI does not require external API keys.

If you wish to use an LLM for instruction parsing:

1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
2. Set your API key(s):
   ```env
   GEMINI_API_KEY=your_key_here
   # OPENROUTER_API_KEY=your_key_here
   # GROK_API_KEY=your_key_here
   ```

## Docker

Run using Docker Compose:

```bash
docker-compose up --build
```

Or build and run manually:

```bash
docker build -t browserflow-ai .
docker run -p 3000:3000 browserflow-ai
```

## API Reference

The server exposes the following endpoints:

- `POST /api/run`: Accepts `{ instruction, headless, aiProvider, apiKeys }` and streams execution logs as Server-Sent Events.
- `GET /api/health`: Returns server status and uptime.
- `GET /api/config`: Returns available configured AI providers.
- `GET /api/screenshots`: Returns a list of screenshot assets generated by runs.
- `GET /api/latest`: Returns the latest run summary and logs.
